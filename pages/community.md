# Community <kbd>0.4</kbd>

## Discussions

Questions and stuff you made with goome go in [Discussions on c-goome](https://github.com/goome-ui/c-goome/discussions). Its on in every goome-ui repo, but c-goome is the main one so thats where most people look. Start with the [welcome post](https://github.com/goome-ui/c-goome/discussions/5).

Something broken goes in an issue on the repo its broken in instead. Security holes go in neither, read [SECURITY.md](https://github.com/goome-ui/.github/blob/main/SECURITY.md) and tell me privately.

I'd love to see what you made with it, a screenshot in Discussions is plenty. Theres also my [Discord](https://sevvy-wevvy.com/discord).

## Good first issues

If you want to help but dont know where to start, these are small on purpose, like a new theme preset or a widget that has no test yet. Each one points at the files you need.

| Repo | Issues |
|:--|:--|
| c-goome | [good first issue](https://github.com/goome-ui/c-goome/labels/good%20first%20issue) |
| csharp-goome | [good first issue](https://github.com/goome-ui/csharp-goome/labels/good%20first%20issue) |
| python-goome | [good first issue](https://github.com/goome-ui/python-goome/labels/good%20first%20issue) |
| java-goome | [good first issue](https://github.com/goome-ui/java-goome/labels/good%20first%20issue) |
| godot-goome | [good first issue](https://github.com/goome-ui/godot-goome/labels/good%20first%20issue) |

Comment on one before you start so two people dont do the same thing. Every repo uses the same labels, `help wanted` is the bigger stuff and `docs`, `backend` and `binding` say what part it touches.

The rules for PRs are on [Contributing](contributing.md). Short version: one thing per PR, against **dev**.
